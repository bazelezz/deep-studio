# Проверка интерфейсов и формы

Дата: 16 октября 2026 года. Локальная dev-сборка: `http://127.0.0.1:3000`.

## Автоматические проверки

Итоговый production-запуск `npm run test:e2e`: **24 теста прошли, 39,0 секунды**. Из них 16 относятся к интерфейсам и форме, 8 — к WebGL-сцене.
Использован отдельный headless Chrome через Playwright, без пользовательского профиля. Конфигурация: `playwright.config.ts`, тесты: `tests/interactions.spec.ts`.

Проверено:

- Все основные разделы доступны, цены показывают «По запросу», отсутствуют пустые внешние ссылки и фиктивные кнопки кейсов.
- Переключение характера меняет вычисленные цвет фона, насыщенность шрифта и пропорции колонок.
- Режим телефона перестраивает демонстрационный интерфейс, скрывает дополнительную навигацию и располагает иллюстрацию после текста.
- Клавиатурное управление переключателями и переходом между двумя композициями работает.
- Каждая из трёх услуг переводит к форме и выбирает соответствующий формат. Работает и параметр `?format=company`.
- Валидация выделяет ошибочные поля и переводит фокус к первой ошибке; проверены пустые поля, некорректные email и короткий телефон.
- Успешный Clipboard API приводит к сообщению о копировании. Текст содержит введённые данные и формат сайта; POST-запросов в деморежиме нет.
- При отказе Clipboard API и резервного `execCommand` появляется доступный для выделения текст; ложного сообщения об успехе нет.
- Мобильное меню закрывается через Escape с возвращением фокуса. Выбор контактов закрывает меню и переводит фокус к разделу.
- На ширинах 375, 390, 768, 1440 и 1920 px нет горизонтального переполнения страницы и переполненных заголовков. Дополнительно проверен смелый вариант демонстрации.
- Без JavaScript серверный контент остаётся доступным, нативное мобильное меню работает. Форма показывает пояснение и не допускает неподготовленной отправки.

Для независимости функциональных проверок использованы `?scene=poster` и `prefers-reduced-motion: reduce`. Этот набор не проверяет WebGL и сценарий движения камеры.

## Границы проверки

Clipboard API дополнительно проверен без подмены: изолированный headless Chrome записал заявку, затем прочитал её и подтвердил содержимое. Отдельные тесты подменяют API для воспроизводимого успеха и отказа; буфер повседневного пользовательского профиля не используется. Реальный endpoint доставки не задан, поэтому реальная отправка не проверялась. Наличие `response.ok` в коде является условием успешной отправки после будущего подключения endpoint.

Оценки Lighthouse, FPS, поведение на физических телефонах и сторонних браузерных движках в этой проверке не измерялись. Production build и WebGL-сценарии проверяются отдельно.

## Повторный запуск

1. Запустить сайт: `npm run dev`.
2. В другом терминале выполнить `npm run test:e2e`.
3. При другом адресе сервера задать переменную `PLAYWRIGHT_BASE_URL`.

Конфигурация использует установленный Google Chrome (`channel: 'chrome'`). Для машины без Chrome необходимо установить браузер или изменить channel на установленный вариант.
